Cupra

Обзор процесса

AS IS / TO BE для автоматизации подбора доп. кодов

AS IS

  1. Пользователь скачивает файл из Belaz.
  2. Пользователь добавляет дополнительную колонку.
  3. Пользователь, используя Постановление, заполняет колонку с доп. кодом.
  4. Пользователь направляет файл в соответствующие организации.

TO BE

  1. Пользователь запрашивает скачивание файла из Cupra.
  2. Система подбирает доп. коды по Постановлению.
  3. Система формирует файл.
  4. Пользователь скачивает файл.
  5. Пользователь направляет файл в соответствующие организации.

US1. Заполнение классификатора РБ

Возможности настройки правил

  • Добавление новых правил для ТНВЭД кодов.
  • Поддержка точного совпадения и масок (например, 0702**).
  • Настройка 4 цифр кода с возможностью фиксированных значений.
  • Гибкая настройка по свойствам ТНВЭД и торговой марки.
  • Фильтрация по ТН ВЭД.
  • Проверка пересечения правил при сохранении и изменении.
  • Поддержка древовидной логики формирования кода.

Хранимые поля классификатора

Поле Требование
Уровень (11, 12, 13, 14) Обязательное
Зависимость от головного уровня Обязательное
Проставляемый код уровня Обязательное
Условия установки уровня (фикс / свойство) Обязательное
Значение условия Обязательное, если выбран тип «Свойство»

US2. Заполнение файла по заказу

Источники выгрузки

  • CustomLight
  • CustomBill

Правила заполнения

  • Если для строки отсутствует правило — ячейка остаётся пустой.
  • Древовидный подбор кода выполняется последовательно до 14 знака.

Алгоритм подбора

  1. Находим основной код (11-й знак).
  2. Проверяем условия текущего узла.
  3. Если условие выполнено — переходим к дочерним правилам.
  4. Повторяем шаги до 14-го знака.
  5. Если ветка обрывается — дополняем нулями (если требуется).

US3. Обработка ошибок и ограничения

Ограничения

  • При добавлении нового ТНВЭД к продаже требуется проверка корректности подбора классификатора.
  • При отсутствии корректного правила требуется доработка классификатора перед выгрузкой.
